Fixed tendon#

Query target: FIXED_TENDON. These are static capabilities; the live session decides which objects and operations are available. See session semantics and write behavior.

Shapes describe tensor dimensions; lanes describe the tuple width, not an extra dimension. Ordering is row-major unless stated otherwise. CPU means host memory; scene device means CPU on CPU/readback scenes or CUDA on DirectGPU; CUDA requires CUDA. Symbolic sizes come from the live group.

tendonInstance#

u64; units: not applicable.

Access

Layout

Memory

Read

fixed, shape [objects], 1 lanes

CPU

Read: requires DirectGPU warmup.

One interned instance token per tendon row, in the same order as the other FIXED_TENDON columns. The row prim is the root prim and may repeat. Pair this token with that prim to match fixedTendonRoot and fixedTendonInstance; that pair is articulation slot T. This row order is database order, not getFixedTendons order.
