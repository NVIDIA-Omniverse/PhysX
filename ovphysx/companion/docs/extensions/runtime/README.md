# Runtime simulation requirements and test specifications

This set derives from the nine reviewed runtime ADRs. Scope is one physics scene, remembered on stage open, loaded only on Play, preserved across Pause, and destroyed on Stop while initial host state is restored. Force load, standalone reset/release and editor maintenance remain unsupported.

The ADRs are **accepted** following design review. REQs are **proposed** acceptance contracts for implementation review. Every TEST is **specification only, not implemented**. No adapter code, automated tests or source `@implements` annotations are added here, and no legacy/current tests are claimed as passing adapter coverage.

These artifacts now live in `ovphysx/companion/docs/extensions/runtime`, beside the imported runtime ADRs, using the repository req/test skill conventions. They specify the extension integration rather than duplicating backend API requirements in the ovphysx tree. The separate [UX requirements/tests](../ux/README.md) cover feature migration and authoring-stage association without expanding this simulation contract.

The one-scene and lifecycle counters below apply to playback owner A. An explicitly requested companion Inspector preview may own independent instance B under the UX design; opening a panel or associating an authoring stage must not create B. B neither drives the timeline nor attaches to A's live source. Process bootstrap is shared and is counted separately from instance creation.

## Fixture and oracle conventions

- Use a fresh live ovstage with required physics schemas registered before population, one physics scene, explicit length units/up-axis and sealed input data. Start CPU fixtures in a process configured before backend initialization. GPU rows run on a provisioned supported device; lack of hardware is an explicit unexecuted row, not evidence of parity.
- Exercise the actual generic Kit hooks for integration cases and the real adapter with boundary spies for unit cases. A host test driver supplies elapsed/currentTime and ordinals deterministically; do not depend on render wall-clock timing. Unit spies must observe production adapter code, not a second implementation of its algorithm.
- Count public step submissions and admitted positive solver intervals separately from any internal zero-time parsing calls; initialization must not advance physics or publish a frame.
- Record instance/attach/detach/destroy counts, live object/resource counts, generation identities, input-drain ranges, submitted/completed step counts, output ordinals/fences and callback order. Where no public accessor exists, add narrow test-only boundary instrumentation with the implementation. Do not add an unsupported public force-load/reset API to make the fixture convenient.
- Assert discrete counts, property existence, identities and ordering exactly. Copied source values and untouched slots restore exactly in their native representation. Derived float32 poses/forces default to absolute tolerance 1e-5 (or a stricter stated tolerance); float16 quaternion comparisons use 2e-3 and account for equivalent quaternion signs. Remainder arithmetic uses 1e-9 seconds against an independent double-precision formula; compare solver motion with explicit fixture tolerances rather than bitwise cross-device identity.
- Read host state and backend results independently. A passing mock call sequence alone does not prove that an object moved or was restored. Pair boundary-count assertions with real ovstage output/live-state reads in integration cases. Never warm up by stepping when verifying Play-without-step or Stop-without-step behavior.
- Snapshot fixtures include nonzero linear/angular motion, missing authored attributes, nested transforms and instancer holes/tail. Separate immutable initial-state data from mutable output-cache baselines. Parameterized type cases assert either the complete declared support path or explicit pre-mutation unavailability; a supported type/mode cannot silently skip required subcases.
- Keep input/output provenance explicit: an inclusive input range may not span a physics-output ordinal. Read the initial snapshot and attach from the same consistent sealed host input; the first attach scan consumes it. Host restoration after Stop does not require a live backend.
- Delay operations with controllable completion events, not sleeps, for teardown/publication tests. Include cleanup in fixture finalization; failing a test must not leave the process-wide attachment owner live for the next case.
- Reentrant requests serialize at completed-substep boundaries. A backend post-step notification proves simulation completion only; presentation tests must wait for ovstage writes and CPU/CUDA completion separately.

Current ovphysx references resolve in the companion checkout (review baseline `a76179e1a8`); historical API review used `c52311f56fb18ac7d8a080440eaa037fb17b665c`. Those paths/APIs are not asserted to exist in the release snapshot.

| Inspected behavior | Adaptation in this specification |
| --- | --- |
| Legacy test_stage_update_attached/resume/reset/detach checks object population 0 → 1 → 0. | Preserve the delayed-load lifecycle, adding fresh-instance/session/resource and ovstage ownership assertions. |
| Legacy test_stage_update_simulate_on/off/simulate_reset checks motion, suppressed stepping and restored position. | Read ovstage world matrices/native arrays/shadows and copied initial state; disabled callbacks provide no editor service. |

| Point-instancer tests check initial velocities and dynamic pose reset; mixed reset variants are explicitly disabled in the old test. | Use Stop and native ovstage arrays; preserved unsimulated slots are a new required case, not falsely attributed to existing legacy coverage. |
| Legacy ray-query tests exercise closest and instancer hits; Raycast.cpp supplies full grab math. | Use ovphysx queries/identity resolution and adapter force oracles. No existing full migrated mouse-force parity test is claimed. |
| Legacy computeSubstepping carries remainder and caps catch-up. | Test the single-scene formula explicitly, including retained backlog, zero-due updates and per-substep force/callback order. |
| Legacy Fabric output tests check motion and pause continuity. | Use ovstage utility outputs and completion fences, without the legacy Fabric scheduling node. |
| Current step_and_write_to_ovstage utility tests use recording stage/physics doubles for mapping, buffers and failures. | Reuse their oracles but add actual adapter step-count, Stop restoration and render-consumer integration assertions. |
| Current attach/detach, ordinal drain and lifecycle failure tests exercise backend contracts. | Add generic-hook Play/Stop, no-step teardown, exclusive ownership and failure-state composition; do not claim those component tests already exercise this adapter. |

## Coverage boundary

These are test specifications, not executed test results. Build/run instructions and executable test locations belong to the implementation change once the adapter exists. That change must add accurate Code References and `@implements`/`@covers` annotations, implement the named cases, and remove specification-only status only after the exact cases pass. Documentation validation here checks unique IDs, ADR/REQ/TEST links, bidirectional maps and coverage of every acceptance criterion.
