# UX requirements and test specifications

**58 proposed requirements, 182 acceptance criteria and 88 test scenarios** derive from 25 revised UX ADRs and the source audit. Tests are **specification only — not implemented**. Existing companion component tests establish their documented service subset; they do not prove full Kit extension parity.

The [ADR index](adr/README.md) now routes UX through companion services and Python USD helpers. The [runtime design](../runtime/README.md) controls playback instance A: one scene, load on Play, retain on Pause, destroy and restore on Stop. Explicit Inspector preview uses an independent instance B. Authoring-stage association does not itself create either instance. C++ remains USD-free; host UI, undo, selection, customer USD and schema access remain Python responsibilities.

The revised proposals restore collision-group authoring and Simulation Info diagnostics, without restoring old Fabric output switching or optional Stop restoration. No new ADR numbers replace the deliberately unused 0006/0007. The companion provider replaces the previous legacy-first/fallback package proposal.

Read the [workflow audit](WORKFLOW-COVERAGE.md), [command catalog](COMMAND-CATALOG.md), [graph catalog](GRAPH-CATALOG.md), [validator catalog](VALIDATOR-CATALOG.md), [configuration mapping](CONFIGURATION-MAPPING.md), and original [108-row feature mapping](FEATURE-COVERAGE.md). A source inventory is coverage evidence, not proof of implemented or tested behavior.

## Fixture and oracle conventions

- Exercise migrated hosts/providers through real Kit commands and the generic lifecycle interfaces. Boundary spies observe production code, not a duplicate implementation. Most cases require integration fixtures; do not infer success from mocked call counts alone.
- Use one physics scene for runnable runtime fixtures. Separate host-stage identity/generation, authoring attachment, selected prim, simulation play generation and operation IDs. Host stage replacement cases are sequential. Inspector additionally owns an explicit independent preview instance B while playback instance A may exist; counters and mutations are scoped to their owner, never aggregated into a singleton assertion.
- Run no-engine, missing-capability and supported-capability variants where specified. A supported variant cannot silently skip subcases. Missing GPU hardware or an unimplemented service is recorded as unexecuted/unavailable, not a passing parity result.
- Capture active layer opinions, composed values, property presence, unrelated sentinels, settings and undo history before authoring. Exact undo restores authored representation and presence; panel opening/rebuilding must not author defaults. Scope removals to the requested APIs and preserve unrelated providers.
- Assert IDs, registration counts, validity, call order, callback pairing and untouched authored data exactly. Derived world/local transforms and query vectors use absolute tolerance 1e-5 unless the fixture states otherwise; compare quaternion orientation allowing q and -q. Derive expected frames and unit conversions independently of widget code.
- Count ovphysx create/attach/step/destroy separately from shared SDK initialization, authoring association and explicit preview creation. Opening UX never creates a Play session. The authoring lifecycle attaches on stage open/late provider registration, remains across Play/Stop, and cannot drive dynamics or output.
- Use completed ovstage output as the simulation oracle where authored USD deliberately differs. Delay asynchronous completion with controllable barriers rather than sleeps; test stale selection, stage, provider and play generations and always finalize owned resources.
- Device, NVTX, cache and bootstrap tests use fresh processes where required. Capture typed config/creation order and process-global ownership; a config getter proves storage only.
