Glossary#

This page explains the words that the ovphysx guides use, grouped by topic. Each entry links to the guide that explains it in full. The names of USD schema types, such as Xformable and Gprim, are defined in Population vocabulary.

Libraries#

ovphysx works together with these libraries:

Term

Meaning

Guide

ovphysx

A library that simulates physics in USD scenes, used through its C API or its Python package.

ovphysx

PhysX

NVIDIA’s physics engine. ovphysx is built on it.

PhysX SDK Documentation

ovstage

The library that loads a USD scene once and keeps it in memory as a stage. ovphysx reads its scene from that stage.

Stages and Ordinals

ovrtx

NVIDIA’s RTX rendering library. It can draw a stage that ovphysx writes its results into.

Showing the Simulation

NVIDIA Warp

The array library that holds the results of every Python read.

Using the Results

Scenes and Stages#

These terms describe how a scene gets into ovphysx:

Term

Meaning

Guide

USD

Universal Scene Description, an open file format for 3D scenes.

Loading Scenes

Prim

One element of a USD scene, such as a box or a joint.

Stages and Ordinals

Path

The name of a prim, made of the names of its parents and its own name, such as /World/Shelf/BoxA.

Path Patterns

API schema

A label on a prim that adds behavior, such as PhysicsRigidBodyAPI, which makes the prim a moving body.

Stages and Ordinals

PhysX schemas

The definitions of the PhysX settings that a USD scene can hold, from the physx-usd-schemas package. Your program registers them before it loads a scene.

Four Steps, in Order

Attribute

A named value. In a scene, an attribute such as physics:mass stores a setting on a prim. In a read or a write, an attribute such as position names the values for each object.

Finding Attribute Names

Stage

A scene held in memory by ovstage, which your program loads and edits.

Stages and Ordinals

Ordinal

A number that your program gives each batch of edits to a stage, higher for each new batch.

Stages and Ordinals

Seal

To mark every edit up to an ordinal as complete, with advance_write_floor. ovphysx reads only sealed edits.

Stages and Ordinals

Attach

To connect ovphysx to a stage with attach_ovstage. ovphysx builds the simulation from the stage at a sealed ordinal.

Four Steps, in Order

Scene update

A change to the scene itself while it runs: your program edits the stage, seals a new ordinal, and calls update_from_ovstage.

Changing the Scene

Physics scene

The PhysicsScene prim, which holds the settings for the whole simulation, such as gravity.

The Physics Scene

Bodies and Colliders#

These terms describe the objects that ovphysx simulates:

Term

Meaning

Guide

Rigid body

An object that moves but never bends, such as a box or a wheel.

Three Kinds of Objects

Dynamic body

A rigid body that physics moves: gravity, contacts, joints, and forces.

Three Kinds of Objects

Kinematic body

A rigid body that your program moves. Gravity and contacts do not move it, but it moves the dynamic bodies it touches.

Moving a Kinematic Body

Collider

A shape that other objects can hit. Applying PhysicsCollisionAPI to a shape prim makes one.

Making an Object Solid

Static collider

A collider that is not part of a rigid body. It never moves, like the ground.

Three Kinds of Objects

Simple shape

A collider shaped as a cube, sphere, capsule, cylinder, or cone. These shapes cost the least and are the most stable.

Simple Shapes

Approximation

The shape that ovphysx builds from the triangles of a mesh collider, such as one convex hull.

Meshes

Convex hull

The tightest shape without dents that wraps a mesh.

Meshes

Material

Settings for how a collider behaves when it touches something: how much it grips and how much it bounces. A material can also set the density that gives a body its mass.

Materials

Soft body

An object that changes shape when it hits something and then returns toward its rest shape, such as a rubber toy. Also called a deformable body. It requires an NVIDIA GPU.

Soft Bodies

Rest shape

The shape that a soft body has when nothing pushes on it.

Soft Bodies

Particles

Small spheres that together simulate liquids and granular material, such as sand. They require an NVIDIA GPU.

Particles

Joints and Articulations#

These terms describe how bodies are connected:

Term

Meaning

Guide

Joint

A connection between two bodies that limits how they move relative to each other, like the hinge of a door.

Joints

Limit

A stop at the minimum or maximum of a joint’s motion, like a door stop.

Limits

Drive

A motor on a joint. It pushes the joint toward a target position, a target velocity, or both.

Drives

Articulation

A set of rigid parts, called links, connected by joints in a tree, such as a robot arm. ovphysx moves the links together, so the joints always hold exactly.

Articulations

Link

One rigid part of an articulation.

Links, Joints, and the Root

Articulation root

PhysicsArticulationRootAPI, applied to the prim that holds an articulation. Without it, the links are separate rigid bodies.

Links, Joints, and the Root

Base

The link where the tree of an articulation starts. A fixed base is attached to the world, and a floating base can move and fall.

Links, Joints, and the Root

Running the Simulation#

These terms describe how the simulation moves forward:

Term

Meaning

Guide

Step

One move of the simulation forward in time, made with step or step_sync.

Steps and Tasks

Time step

The simulated time that one step covers, the dt that your program passes. These guides use 1/60 s.

The Time Step

Task

A receipt for queued work, such as a step. Your program waits for each task once.

Steps and Tasks

Solver iterations

The passes that PhysX makes in each step to correct positions. More iterations hold stacks and joints better but take more time.

What to Change

Environment

One self-contained setup, such as a robot and the objects it works with, under its own prim.

Environments and Copies

Clone

To copy an environment many times in the simulation only, for robot training. One read returns the state of every copy.

Clone an Environment

Reading and Writing#

These terms describe how your program gets values out of the simulation and puts them in:

Term

Meaning

Guide

Object type

The kind of object that a query selects, a SimObjectType such as RIGID_BODY.

Object Types

Query

A selection of objects by type, and optionally by path pattern. Reads and writes act on a query, and your program can keep one to reuse it.

Keeping a Query

Path pattern

A path with wildcards, such as /World/Box*, that narrows a query to part of the scene.

Path Patterns

Read

A request for attributes of the objects that a query selected. It returns arrays with one row per object.

Reading Values

Group

One part of a read or write: the values of one attribute and the list of objects that they belong to.

Reading and Writing State

Write

A change that your program makes to the simulation, such as a velocity or a force. It has three steps: open, fill, and commit.

Open, Fill, Commit

Commit

The last step of a write. ovphysx applies the values of a group at once, before the next step.

Open, Fill, Commit

Mask

An array with one value for each row of a group. A commit with a mask skips the rows whose value is zero.

Open, Fill, Commit

Contact sensor

A body that reports the contact forces it receives, made with PhysxContactReportAPI.

Contact Sensors

CPU and GPU#

These terms describe where the simulation runs and where its results are:

Term

Meaning

Guide

Default mode

With an NVIDIA GPU, physics runs on the GPU, and ovphysx copies most results to CPU memory after every step.

Where Results Are

CPU mode

Physics and results both stay in CPU memory. On a computer with an NVIDIA GPU, set OVPHYSX_DISABLE_GPU=1 to use it.

CPU and GPU

DirectGPU

A mode in which simulated values stay in GPU memory, ready for code that runs on the GPU, such as a PyTorch network.

Turn On DirectGPU

Warp array

The warp.array that every Python read returns. For results in CPU memory, numpy() gives a NumPy array.

Using the Results

CUDA graph

A recording of GPU work, such as reads, a policy network, and writes, that replays with one launch.

Replay a Loop With a CUDA Graph

Seeing and Debugging#

These terms describe the tools that show what the simulation does:

Term

Meaning

Guide

Debug view

Lines that show what PhysX works with, such as the collision shape of every object and every contact. Your program turns it on by writing to the DEBUG_RENDER target, and your renderer draws the lines.

See What PhysX Sees

OmniPVD

The PhysX Omniverse Visual Debugger. It records what PhysX simulates at every step into a .ovd file, which a viewer replays.

Record and Replay With OmniPVD

Log level

How much ovphysx prints. By default, it prints messages of level WARNING and above.

Turn Up the Log Level
