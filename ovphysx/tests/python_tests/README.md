# Python tests

Run from this directory using the wrapper (recommended):

```
./run_pytest.sh -q
```

On Windows:

```
run_pytest.bat -q
```

The wrapper runs `uv run --locked pytest` to prevent lockfile changes.

Bare `uv run pytest` can re-resolve dependencies and update the lockfile.

Tests run against the in-tree SDK build: set `OVPHYSX_LIB` before invoking
pytest if you need to point at a non-default build output.

## Lockfile maintenance

`uv.lock` is generated by `uv` and should not be edited manually. If it becomes
stale or invalid, regenerate it from this directory:

```
uv lock
```

Nothing has to be staged first: `pyproject.toml` declares an `explicit`
`[[tool.uv.index]]` named `ovstage` and pins the package to it in
`[tool.uv.sources]`, so `uv` resolves it from that index and records a URL plus a
sha256 per wheel. `scripts/validate_python_test_uv_lock.py` enforces both, and
`scripts/sync_ovstage_version.py` regenerates the lock whenever the pin or the
channel changes.

`pyproject.toml` declares `tool.uv.required-environments` for Linux x86_64,
Linux aarch64, and Windows amd64 so the lock resolves ovstage for every CI host.

CI rejects local OVStage registry paths and missing or invalid SHA-256 hashes.
