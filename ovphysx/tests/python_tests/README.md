# Python tests

Run from this directory using the wrapper (recommended):

```
./run_pytest.sh -q
```

On Windows:

```
run_pytest.bat -q
```

The wrapper runs `uv run --locked pytest` with `UV_FIND_LINKS` pointed at
`_build/target-deps/ovstage_wheel`, matching CI. That prevents accidental
`uv.lock` rewrites when validating local test changes.

Do **not** use bare `uv run pytest` for routine iteration; it can re-resolve
ovstage from PyPI (same version pin, different lock entries).

Tests run against the in-tree SDK build: set `OVPHYSX_LIB` before invoking
pytest if you need to point at a non-default build output.

## Lockfile maintenance

`uv.lock` is generated by `uv` and should not be edited manually. If it becomes
stale or invalid, regenerate it from this directory after placing the CI platform
ovstage wheels under `../../_build/target-deps/ovstage_wheel/` (fetch via
`scripts/fetch_ovstage_release.py` for each platform, or copy from a build):

```
uv lock
```

`pyproject.toml` sets `tool.uv.find-links` to that directory so regeneration
prefers build-staged wheels over PyPI. Run `build.sh` first so the wheels exist.

`pyproject.toml` declares `tool.uv.required-environments` for Linux x86_64,
Linux aarch64, and Windows amd64 so the lock resolves ovstage for every CI host.

CI and `scripts/validate_python_test_uv_lock.py` reject accidental lock changes
that point ovstage at PyPI URLs instead of local wheel paths.
